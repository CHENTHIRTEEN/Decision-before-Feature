Pflacco: Feature-Based Landscape Analysis of Continuous and Constrained Optimization Problems in Python

Heike Trautmann trautmann@uni-muenster.de Department of Information Systems, University of Münster, Münster, 48149, Germany Data Management and Biometrics, University of Twente, Enschede, 7522, Netherlands

Abstract
The herein proposed Python package pflacco provides a set of numerical features to characterize single-objective continuous and constrained optimization problems. Thereby, pflacco addresses two major challenges in the area of optimization. Firstly, it provides the means to develop an understanding of a given problem instance, which is crucial for designing, selecting, or configuring optimization algorithms in general. Secondly, these numerical features can be utilized in the research streams of automated algorithm selection and configuration. While the majority of these landscape features are already available in the R package flacco, our Python implementation offers these tools to an even wider audience and thereby promotes research interests and novel avenues in the area of optimization.
Keywords
Exploratory landscape analysis, Python, fitness landscape, problem understanding, continuous optimization, automated algorithm selection.
1 Introduction
Up until now, the arguably most comprehensive software package for landscape analysis in the single-objective continuous optimization domain is the R package flacco (Kerschke and Trautmann, 2019b). However, Python became much more disseminated in the past decade. To make the continuous form of landscape analysis more accessible to a broader audience and to facilitate automated algorithm selection (AAS) approaches (Kerschke et al., 2019), an early version of the Python package pflacco1 was created in 2019. This preliminary version 0.*.* provided a simple interface to the R package flacco and was used in several publications over the coming years (Prager et al., 2021, 2022; Tanabe, 2021, 2022; Seiler et al., 2022; Rizk et al., 2022; Vodopija et al., 2022). While there is certainly merit in having a single code base in terms of maintainability, an interface to a secondary external programming language introduces an enormous computational overhead. From a user’s perspective, this rarely holds any value as it increases the required CPU time. This, in turn, can lead to the dismissal of this particular

As previously mentioned, pflacco does not contain all feature sets which are available in the R version. These are the “barrier tree” and “generalized cell mapping” features. This is justified by the fact that, to the best of our knowledge, only a very few publications have made use of these features since their inception. Note that these features are published in conjunction with other feature sets. As a result, although these publications receive frequent citations, the two feature sets mentioned earlier are rarely utilized by the works that cite them. Even on the few occasions they are used, the effect of these features remains limited at best. We, therefore, conclude that there is currently little demand for these features by researchers.
2 Scope of Pflacco
Optimization algorithms and the respective optimization problems they aim to solve are ubiquitous in theoretical research and real-world applications. Pivotal for this research area is to develop a general understanding of the underlying optimization problem. Contributing to the complexity of this endeavor is the fact that optimization problems can be heterogeneous in nature. An optimization problem can be smooth with a single strong basin of attraction, more rugged but with a strong global structure, or highly multimodal with no apparent global structure. This can be gauged visually for 2D optimization problems but becomes increasingly difficult for problems of higher dimensionality. The Python package pflacco alleviates this issue by providing a multitude of numerical values for a given single-objective continuous optimization problem. The origin of this package and flacco can be traced back to the work of Mersmann et al. (2011). The proposed sets of landscape features (also known as Exploratory Landscape Analysis (ELA)) can be used to assess certain high-level properties (e.g., the degree of multimodality) of a given problem instance based on a small sample of function evaluations. While pflacco encompasses these feature sets, it also provides the functionality to create local optima networks (Adair et al., 2019). While these networks also provide a set of numerical features, a visualization (which is currently not provided by pflacco) of these networks gives insight into the fundamental topology, even for high-dimensional optimization problems. This visualization can be used to detect the presence and strength of funnel structures. A full list of the implemented features, the recommended sample size, and their original paper can be found in Table 1. The suggested sample size is derived from the findings of the respective sources and should be deviated from with care. Past research for a variety of ELA features suggests that a sample size of 50D suffices, where D is the dimensionality of the problem instance (Kerschke and Trautmann, 2019a). On the other hand, for feature sets such as the ‘gradient’ features, only the suggestion of the original author exists, which is 1,000D.

Whereas the first major use case of pflacco is problem understanding, which requires a certain degree of expertise, the second one relates to the area of AAS and configuration (Kerschke et al., 2019). The central component of an algorithm selector often is a machine learning (ML) model. This ML model maps a problem instance i ∈ I to a specific algorithm a ∈ A; that is, it aims to predict the optimal algorithm a of an algorithm portfolio A for a given problem instance i. In general, an ML model operates on numerical data where the landscape features of pflacco are useful. These features f (i) can be used to quantify an unseen problem instance i and serve as a numerical surrogate of i. This enables an ML model to process this information and select an appropriate algorithm a. The training of such an algorithm selector and its usage after training is illustrated in Figure 1. 3 Summary and Future Work
To the best of our knowledge, pflacco is the first Python package which offers a wide variety of different landscape features. Many publications use different programming languages, only publish their code to a GitHub repository, or obfuscate their work entirely. For the programming language Python, at least, we hope to provide the means to analyze optimization problems from a theoretical perspective as well as to use the landscape features in more experimental works such as AAS. If even more widely used, pflacco will foster comparability and reproducibility of experimental studies in AAS and single-objective continuous black-box optimization. While similar, the packages flacco and pflacco differ in some aspects. flacco offers a graphical user interface (GUI) which lowers the barrier of entry for inexperienced developers, and can be used to visualize and dissect landscape features from a different vantage point. pflacco does not offer this functionality because the benefit of offering an additional GUI is severely limited. To start flacco’s GUI, very little understanding of the programming language R is required. Thereafter, the interaction between user and GUI does not require any knowledge about R at all. Hence, we refer any user who is interested in interacting with a GUI, instead of the underlying programming language, to flacco. In contrast to flacco, pflacco offers the opportunity to create local optima networks and derive landscape features based on these networks. Furthermore, pflacco has an operational continuous integration pipeline including unit tests for different operation systems and Python versions. This facilitates stable releases and gives other researchers the ability to directly contribute to pflacco via the respective GitHub page without the need of extensive review from existing developers. In version 1.2.*, a current limitation of pflacco is that the ELA levelset features are only partially supported. This is due to the fact the required mixture discriminant analysis is not publicly available in Python. We plan to implement this functionality as well as to incorporate additional feature sets, such as the work of Shirakawa and Nagao (2016), Derbel et al. (2019), and Agasiev (2020), in the near future.
