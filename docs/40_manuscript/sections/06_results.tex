\subsection{RQ1: What is the state-conditional value of the primary query?}

RQ1 concerns \query{} with $\lambda_T=1$ and $\lambda_M=0$ on SBS-prefix states
emitted by the prespecified dynamic opportunity process.  It reports the joint Query utility, Behavior-only utility, and their operational increment together with terminal and continuation-only endpoints.  Query terminal gap, observed target hit, and ERT include the best point in the query sample; path completion and completion-conditioned endpoint success are reported separately.  The sample contribution is also shown separately.  In the interpretation of RQ1, the query path is judged against the best available no-query policy, so Behavior-only is the primary comparator and native Skip remains the secondary no-query reference.  The active protocol uses five paths—Skip, Behavior-only, sampling-only, query-matched state-only, and full Query—so any residual four-action wording in earlier drafts should be read as shorthand for the query-acquisition matrix rather than the full operational protocol.

\subsection{RQ2: Does Behavior add decision value beyond elapsed budget?}

Model-family selection uses B3 only and the concatenated outer-holdout
first-trigger $G_FE$.  These outcomes select among candidates and provide
development diagnostics; after selection they are not an unbiased estimate of
the selected procedure.  AUROC, average precision, and Spearman correlation
are secondary; continuous-Utility RMSE is defined only for Ridge.  After the
model family is predefined, B3 is compared with T0 on the same 12 mandatory
milestone rows.  This prespecified BBOB-validation B3--T0 comparison is a
post-development internal finite-set estimate, not an independent confirmation;
external suites are evaluated separately.  A dimension-stratified T0 fit,
whose within-stratum input remains FE ratio only, is a static-context diagnostic
and does not add dimension to the primary Decision input.

share one native outcome.  Always Query and Traditional pre-run AAS are distinct:

and starts one selected algorithm from native initialization.  The
self-thresholded Behavior-only policy has its own $U_b$ threshold; the
matched-trigger Behavior-only diagnostic used for $query_operational_increment$ is not a baseline.
