# Original Logic Map

## Overall manuscript logic before the present journal-style revision

The draft already contained a rigorous frozen protocol, but its argument was diluted by two competing modes of exposition. The scientific mode defined the decision time, utility, behavior, downstream selector, splits, and RQs. The execution-report mode narrated local result availability, generation stages, storage objects, commands, and handoff status. The latter made the experimental and reproducibility sections read as a project report and detached Results placeholders from the contribution promises they must eventually test.

## Unit-by-unit map

| Original unit | Intended scientific function | Logic or rhetoric problem identified | Required destination in the revised logic |
|---|---|---|---|
| Title, Abstract, Highlights | State the new decision problem, method, and principal evidence | Method claims and pending outcomes coexisted, but the evidence contract needed an explicit boundary for each RQ | Retain the precise query-acquisition title; keep method statements direct and bind all outcome sentences to the five Abstract TBD identifiers |
| Introduction opening | Move from black-box portfolio heterogeneity to ELA-based AAS | Background risked treating landscape acquisition as an unexamined standard step | Make the obligatory sample--feature--selector workflow the premise, then expose acquisition cost as the problem |
| Introduction trajectory paragraphs | Establish that native optimizer history may contain usable pre-query information | Trajectory representation, algorithm selection, and query-value prediction could be conflated | Distinguish reused trajectory information from a separate landscape query and state that informativeness for another task is not evidence of utility prediction |
| Introduction generalization paragraph | Motivate strict splits and external evaluation | Could be read as implying that the proposed family split guarantees transfer | Use prior failures only to justify the test; state that held-out and external success remain open |
| Introduction task and contributions | Name Decision-before-Feature and its contributions | Empirical value could be mistaken for an established contribution | Limit confirmed contributions to formulation, labels, information boundary, selector separation, and evaluation design |
| Related Work: landscape/AAS | Establish conventional representation-to-action selection | Earlier organization was more enumerative than comparative | Compare the decision object and the time at which representation exists |
| Related Work: acquisition cost | Show why a descriptor call cannot be assumed free | Reused samples risked being described as eliminating all cost | Separate objective-evaluation sampling cost from representation computation time and memory |
| Related Work: warm-started per-run selection | Place Jankovic and Kostovska as closest antecedents | Their fixed CMA-ES prefix and second-stage action could look identical to the proposed gate | Contrast direct action selection with the pre-query acquisition decision, and distinguish optimizer-specific state from algorithm-agnostic behavior |
| Related Work: trajectory and behavior | Support interpretable native-history summaries | Problem classification and whole-run similarity could be overextended into predictor validity | Use DynamoRep, Opt2Vec, STN, Hayward, and Mbasso for representation vocabulary only, with explicit prohibited inferences |
| Related Work: adaptive search | Separate this work from operator control, dynamic AS, and MetaBBO | The term “controller” could blur offline supervised gating with online learned search | State that the method leaves portfolio algorithms unchanged and trains no online update rule |
| Related Work synthesis table and gap | Make novelty assessable on fixed axes | An absolute priority statement would exceed the reviewed corpus | Compare decision target, information time, query FEs, internal inputs, and transition; use corpus-scoped novelty wording |
| Problem Formulation | Define state, query/no-query paths, utility, label, and diagnostic decomposition | Exact definitions were sound but needed a clearer claim boundary | Preserve equations and end by stating what the estimand does not establish |
| Method overview and figure | Separate offline label construction from online execution | Engineering process narration could dominate the scientific architecture | Present the architecture through information timing and supervised roles, not local pipeline artifacts |
| Native history and behavior | Define full-state replay, window anchors, invariance, and maturity variables | Search Maturity could be read as an established mechanism | Keep it operational and hypothesis-bearing; reserve validation and interpretation for RQ5 |
| Selection Reference | Define four-action loss regression and transition relations | The fixed Random Forest could be mistaken for the main novelty; retrospective minima could be called an oracle | Label it a downstream reference, retain “best observed action,” and keep transition relations explicit |
| Decision Model | Define active candidates, nested family OOF selection, and threshold fitting | T0 or validation could inadvertently influence model selection | State the single B3 model-family selection, then fit the same family separately to T0--B3 with train-only thresholds |
| Experimental Setup | Specify RQs, benchmarks, queries, opportunities, populations, baselines, metrics, and inference | Original prose described local result objects and generation order like an experiment report | Organize around estimands and contrasts; retain scientific dependencies only where they define analysis populations |
| Results | Provide tables, figures, tests, and answers for RQ1--RQ5 | Earlier status narration referred to withdrawn/regenerated files and made placeholders look like workflow updates | Use neutral evidence-availability language and make every subsection table/figure/statistic/answer map to one contribution promise and TBD product |
| Discussion | Interpret mechanisms, scope, and limitations | Without results, polished prose could silently upgrade questions to findings | Retain six evidence-specific TBDs and state only the methodological separation at full strength |
| Reproducibility | Enable independent reconstruction of the scientific study | Local paths, formats, commands, readers, and generation order belonged to project documentation, not a journal article | Describe software versions, explicit random streams, exact-FE state keys, scientific dependencies, consistency conditions, resource measurement, and reconstructible summaries |
| Conclusion | Close on answer and significance | Pending effects and external transfer could be phrased as accomplished | Confirm the method definition, retain RQ-specific conclusion TBDs, and bound any future robustness claim to the three evaluated query configurations |

## Preserved load-bearing logic

The revision must not alter the shared-state estimand; the primary \(\lambda_T=1,\lambda_M=0\) target; the four unique actions and transition semantics; complete-native-update behavior windows; B3-only model-family selection among LDA, Logistic Regression, and Ridge; train-family OOF threshold fitting; BBOB-validation's evaluation-only role; the required baselines; or the 38 TBD-to-product mappings.
