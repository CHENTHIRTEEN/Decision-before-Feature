# Behavior-with-ELA Phase 1–2 实验结果报告（2026-08-28）

本文档汇总 behavior_with_ela 实验线从配置修订到 Phase 2 增量检验的主要结论，供后续分析使用。
所有科学产物位于 `behavior_with_ela/results/`（原始数据不进 git）。

## 0. 协议与配置决策

| 决策 | 结论 | 依据 |
|---|---|---|
| CEC2017 F30 | **移除**（保留 F1, F3–F29 共 28 题） | opfunu 1.0.1 的 cec2017 模块只实现到 F29（无 `F302017` 类）；更换依赖属无端复杂性 |

## 1. Phase 1 离线数据（已完成，0 失败）

- **collection**：48 shards（bbob_train 18 + mabbob_train 24 + bbob_validation 6），共 2,880 次 optimizer run。
- **action_gain_dataset**：135,417 行 / 45,139 个 decision state（bbob_train 76,407；mabbob_train 33,696；bbob_validation 25,314）。
- decision label（`action_gain_class`，practical delta 生效后）：总体 equivalent 48.4% / degrade 27.6% / improve 24.0%。
- 一致性核对全部通过：`handoff_required == not action_equals_prefix`（逐行）；`handoff_type` 与切换关系 2×2 对齐；`all_action_paths_completed` = 100%；decision 侧 `bf_*` = 29 列（28 selector + `bf_search_maturity_linear`）。
- **修复记录**：`action_dataset.py` 原用 `pd.read_parquet(...).to_dict("records")` 读取轨迹，pandas 把 `list<struct>` 列变成 numpy array 导致 `extract_behavior_rows` 报"missing native-update window statistics"。已改用主实验成熟路径 `read_trajectory_rows`（pyarrow to_pylist + 文件校验）。collection 产出的 parquet 本身无问题。

## 2. 成熟度形式的处理

- Phase 1 模型固定使用 28 列无成熟度行为特征（`SELECTOR_BEHAVIOR_FEATURE_COLUMNS`，代码断言强制），与主实验规范"下游 Selector 不使用成熟度字段"一致。
- 成熟度只进入 Phase 3 的 G_FE Gate，且已被 behavior_with_ela **预指定为 `bf_search_maturity_linear`**（`action_dataset.py` 取 `B2+Motion+SearchMaturityLinear` 组；`phase3.py` 硬断言恰附加该字段）。
- 若需补齐三形式消融：`behavior.parquet` 已物化全部三种形式（非空），另两种形式是数据集中 9 个基础行为列的确定性函数（`behavior/features.py::_maturity_features`），复用 `_family_oof_predictions → fit_first_trigger_threshold` 各跑一次即可，无任何新实验运行成本。

## 3. Phase 1 模型与 Go/No-Go（结论：**Go**）

模型：per-action 三分类 RF（200×8, sqrt, balanced_subsample），5 个 BBOB function family 折 OOF，50,938 条 OOF switch 行；**decision threshold = 0.2445**；SBS = cmaes；noise delta = 1.464（95% 分位）→ practical gain delta = **1.464**（等价带宽，解读标签时注意口径）。

| §16.2 判据 | 结果 | 判定 |
|---|---|---|
| Behavior-only 明显优于 time-only（grouped OOD） | train OOF gain 0.847 vs 0.435；validation 1.448 vs 0.841；sign 指标同向（AP 0.264 vs 0.179，基线率 0.140） | ✅ |
| sign AP / balanced accuracy 稳定增益 | AP 0.264（1.9× 基线率）、balanced acc 0.568、macro F1 0.543；但 **cmaes 行内 AP 0.251 < 基线率 0.291**（pso/shade 强） | ✅（附 cmaes 弱点） |
| selected action regret 显著低于 Continue/Random | validation 归一化 regret 0.256 < continue 0.539 < random-matched 1.006 < random 1.138 | ✅ |
| 不同 dimension 无反向结论 | Phase 1 协议固定 10D，按设计延后 | — |
| paired repetitions sign-flip rate 可接受 | 36,320 条重复 switch action：均值 5.7%，中位数 0，83.3% 零翻转 | ✅ |

**必须记录的发现**：基线中的 `behavior_action_loss_rf`（动作损失回归式 RF，单模型多输出，分数语义 = 预测 log10 loss 优势）在两个 split 上都**强于**三分类主模型（validation gain 1.850 vs 1.448，归一化 regret 0.164 vs 0.256）。这不阻塞 Go，但它是 Phase 1 更强的载体，Phase 2 对照因此同时检验两个载体。

产物：`results/model/behavior_action_gain/`（models.joblib、oof_*、threshold_summary、validation_*、training_summary.json）、`results/baselines/phase1/`（18 份 policy summary）、`results/model/traditional_aas/`（780 states）、`results/traditional_aas/`（FE=0 描述符 shards）。

## 4. 工程修复：阈值扫描向量化（协议不变，已对拍验证）

原 `fit_first_trigger_threshold` 逐阈值逐 run 重放：约 21,000 个候选阈值（RF 概率高基数）× 3.9 s/阈值 ≈ **23 小时**，且 phase2/baselines 复用同一函数。已重写为：每 run 一次性预计算 state-best 上下文（排序键与原实现逐位一致）+ 分数升序后缀最小位置 + `searchsorted` 对全部阈值并行求解。**对拍验证**：30 个采样阈值（含恰好等于分数值的边界）最大指标差 2.8e-16（纯浮点求和顺序），提速 499×，全量扫描 1 秒。被选中阈值的 run 级明细表仍走原 `replay_first_trigger` 路径。phase2.py / baselines.py / phase2_action_loss_increment.py 均经 `model.py` 导入自动继承。

## 5. Phase 2：Local Landscape 增量（结论：**增量未确立**）

运行一：`phase2.py`，三分类载体，特征组 M0 time-only / M1 behavior / M2 lf_* 单独 / M3 behavior+lf / M4 +uncertainty。
运行二：`phase2_action_loss_increment.py`（新模块），action-loss 载体，特征组 A1 / A3 / A4。为支持该对照，baselines.py 的三个 action-loss 函数参数化了 `feature_columns`（默认值不变，既有调用零行为变化）。

### 5.1 三分类载体（function-balanced）

| 特征组 | 特征数 | train OOF gain | train 归一化regret | val gain | val 归一化regret |
|---|---:|---:|---:|---:|---:|
| M0 time-only | 1 | 0.4352 | 0.6700 | 0.8411 | 0.5973 |
| M1 behavior（=Phase 1） | 28 | 0.8467 | 0.4023 | 1.4532 | 0.2527 |
| M2 lf_* 单独 | 23 | 0.8520 | 0.3710 | **1.4658** | 0.2357 |
| M3 behavior+lf | 51 | 0.8776 | 0.3766 | 1.4254 | 0.2472 |
| M4 +uncertainty | 63 | **0.8859** | **0.3268** | 1.2583 | 0.2903 |

逐 run 配对增量（协议主证据）：

| 对比 | train OOF Δgain / Δregret | validation Δgain / Δregret |
|---|---:|---:|
| M3−M1 | +0.0309 / −0.0309 | **−0.0278 / +0.0278** |
| M4−M3 | +0.0084 / −0.0084 | **−0.1671 / +0.1671** |

### 5.2 action-loss 载体

| 特征组 | train OOF gain | val gain | val 归一化regret |
|---|---:|---:|---:|
| A1 behavior（28） | 1.3141 | 1.8504 | 0.1636 |
| A3 +local（51） | 1.2508 | 1.8504 | 0.1636 |
| A4 +uncertainty（63） | 1.2683 | 1.8504 | 0.1636 |

配对增量：A3−A1 train OOF **−0.063**；validation **精确为 0**。合理性检查：A1 与 A3 的验证集预测分数确实不同（相关 0.959、平均差 0.398），但符号一致率 100%，first-trigger 决策完全重合——真实结果，非代码错误。

### 5.3 解读

1. 零额外 FE 的 local landscape 特征在 held-out function family 上没有稳健正增量：三分类载体的 train OOF 小增量（+0.031）不能迁移（−0.028），uncertainty 在 validation 上明显有害（−0.167）；更强的 action-loss 载体上增量为零或为负。
2. **值得记录的观察**：M2（lf_* 23 列单独）是 validation 上最好的组（1.4658 > M1 1.4532），train OOF 上也略高于 M1——`lf_*` 自身携带的信息不弱于 `bf_*`，但两者合并不增益（冗余或验证集 6 函数/540 run 的小样本波动，待诊断）。
3. 按 Phase 门槛逻辑（与 Phase 1"不成立就停止扩展 online ELA"同构），**不支持在当前证据上叠加 Phase 3 adaptive query**；建议先做 M2 现象诊断（驱动列 + leave-one-function-out 稳健性），再决定 Phase 3。

产物：`results/model/local_landscape_increment/`、`results/model/local_landscape_increment_action_loss/`（各含 model_summary.parquet、increment_contrasts.parquet、thresholds.parquet、first_trigger_runs、模型 bundle）。
